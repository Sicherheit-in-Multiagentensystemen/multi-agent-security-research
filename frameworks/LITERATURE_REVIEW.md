# 文献整理与综述流程

## 先限定研究问题

为每轮整理写一句可回答的问题，例如：“在只能污染一名 worker 输出的条件下，跨代理来源追踪是否降低未授权工具调用，同时保留正常任务完成率？”记录系统类型、攻击者能力、结果指标、对照组和资源上限。

## 检索与筛选

1. 在 arXiv、ACL Anthology、PMLR、NeurIPS、OpenReview、安全会议和原作者项目页检索。搜索引擎只做发现，元数据与结论回到原始来源核验。
2. 保存检索日期、精确查询词、来源、纳入/排除原因。参考[本次检索记录](../docs/SEARCH_LOG.md)。
3. 按 DOI、arXiv ID 和标题去重。预印本与正式版视为同一研究的不同版本；若作者或结果变化，在引用中固定所用版本。
4. 优先纳入直接研究 MAS 的攻击、防御和评测；对单 agent、MARL、分布式基础和安全应用单独打标签。
5. 保留排除记录。仅讨论一般聊天模型越狱、没有系统边界且缺乏可迁移问题的文章，不直接进入 MAS 核心清单。

## 提取证据

使用[论文阅读模板](../templates/PAPER_NOTE.md)。至少记录：研究问题、系统与拓扑、攻击入口、控制范围、方法、对照、模型与代码版本、成功判据、预算、正常效用、局限、精确来源位置。

将笔记分成三块：**作者报告**、**整理者解读**、**独立验证**。摘要核查不能标为全文精读；读过代码不能标为复现；成功运行脚本不能自动标为复现论文结果。

## 评价证据强度

| 状态 | 含义 |
| --- | --- |
| `discovered` | 只发现链接，尚未核验 |
| `metadata-and-abstract-checked` | 核对了原始元数据和摘要 |
| `full-text-reviewed` | 阅读全文并提取具体页码、表格与假设 |
| `artifact-inspected` | 检查了指定版本的代码或数据 |
| `reproduced` | 在记录完整环境和配置后复现实验，结果可查 |

发表状态与证据核查状态分别记录。同行评审、理论证明、开源代码和独立复现是不同维度，不合并为一个“高质量”分数。

## 综合与写作

按“威胁模型 → 机制 → 防御 → 评测 → 未解决问题”组织综述。只有在任务、模型、攻击预算和指标定义可比时才比较数值；其余使用定性证据表。负结果、失效条件和适用范围应与成功案例一起记录。

每个潜在研究空白写成可证伪的假设，附最小实验、对照、判定标准和预期资源。不能仅因本仓库没收录相关论文就断言领域不存在该工作。

本流程是轻量化整理规范；本次首批整理没有执行完整系统综述流程，也不声称检索穷尽。
