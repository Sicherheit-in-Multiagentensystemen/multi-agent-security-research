# 多智能体安全评测框架

本框架是本组织拟采用的实验记录规范，尚未对应已运行的评测结果。

## 先固定比较条件

记录模型与快照日期、框架与代码提交、代理数量、角色、拓扑、共享状态、工具权限、任务集、攻击入口、攻击者能力、轮次、随机种子和成本上限。同一任务比较无攻击、受攻击无防御、受攻击有防御、无攻击有防御四种条件。

## 指标与分母

| 指标 | 建议定义 | 注意事项 |
| --- | --- | --- |
| 攻击成功率 ASR | 达成预定义攻击目标的有效受攻击运行数 / 有效受攻击运行数 | 在运行前定义目标，逐项报告；API 错误另列 |
| 正常任务完成率 | 成功完成用户任务的有效运行数 / 有效任务运行数 | 分别报告无攻击与有攻击条件 |
| 条件攻击成功率 | 在无攻击基线可完成的同一组任务上测量 ASR | 与总体 ASR 同报，防止基线能力不足掩盖风险 |
| 传播比例 | 非初始受控节点中被判定失陷的节点数 / 非初始受控节点总数 | 标明时间/轮次、失陷判据，转发消息不自动算失陷 |
| 首次失陷时间与传播深度 | 首次满足失陷条件的轮次；观测到的传播链长度 | 明确链路追踪方法与删失运行 |
| 未授权动作率 | 发生未授权实际副作用的运行数 / 有效运行数 | 区分计划、尝试、被拦截与执行成功 |
| 安全税 | 无攻击任务完成率在启用防御前后的差值，以百分点报告 | 同报延迟、token、费用和误拦截 |
| 可用性损失 | 相对基线增加的时间、调用量及预算耗尽率 | 超时阈值在实验前固定 |
| 恢复能力 | 撤销污染、隔离节点后恢复任务的比例与耗时 | 区分恢复状态和恢复任务效用 |

当代理数为 1 或没有非初始受控节点时，传播比例为“不适用”，不能填 0。小样本给出原始成功数、分母和置信区间，不能只保留百分比。运行因模型拒绝、工具校验拒绝、网络错误或预算耗尽而结束时，原因要分别记录。

## 最小实验矩阵

| 因素 | 起步取值 |
| --- | --- |
| 结构 | 单代理基线、层级团队、点对点团队 |
| 入口 | 工具输出、代理间消息、共享记忆 |
| 防御 | 无防御、提示防御、权限执行、来源保留及其组合 |
| 攻击能力 | 固定消息污染、自适应攻击；预算分别锁定 |
| 任务 | 正常任务、含攻击任务、合法但容易被误拦的任务 |

这些取值是实验建议，不表示本仓库已有覆盖全部组合的数据。

## 防止评测误导

- 防御能看到的信息与实际部署时一致；不能把攻击标签泄露给检测器。
- 以工具状态和审计日志核验副作用；模型声称成功不足以判定攻击成功。
- 用未见任务和自适应攻击检验泛化；记录用于调试防御的数据。
- 保持语义不变地修改工具命名或格式，检查是否仅依赖表面提示。
- 不混合不同论文、版本、模型和预算下的 ASR 做排名。

设计参考 [AgentDojo](https://arxiv.org/abs/2406.13352)、[InjecAgent](https://arxiv.org/abs/2403.02691)、[Security Tax](https://arxiv.org/abs/2502.19145)、[定量评测方法](https://arxiv.org/abs/2507.21146)和 [Representation Sensitivity](https://arxiv.org/abs/2610.03585)。具体记录使用[实验模板](../templates/EXPERIMENT.md)。
